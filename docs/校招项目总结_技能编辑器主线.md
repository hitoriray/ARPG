## 1. 项目一句话定位

这是一个 Unity ARPG 客户端项目，核心特征是：

- 战斗层采用 `Arch ECS + 固定步长` 的运行模式。
- 技能系统走“**数据驱动 + 帧事件时间轴**”路线。
- 自研了可直接生产技能数据的 `SkillEditor`（UIElements + 场景预览 + Inspector + Gizmos）。
- 客户端链路完整覆盖了 `输入 -> 技能释放 -> 命中结算 -> UI反馈 -> 存档`。

## 4. 主线亮点：技能编辑器（SkillEditor）

## 4.1 设计目标

SkillEditor 不是“演示工具”，而是实际可编辑并持久化 `SkillClip` 的生产工具，目标是：

- 让策划/客户端在时间轴上直接编辑技能帧事件
- 所见即所得预览动画、音效、特效、命中区域
- 编辑后直接回写配置，运行时可立即消费

## 4.2 编辑器入口与工作台

关键代码：

- `Assets/SkillEditor/Editor/EditorWindow/SkillEditorWindow.cs:20`  
  菜单入口 `Skill Editor/Skill Editor Window`
- `.../SkillEditorWindow.cs:98`  
  编辑器专用场景 `Assets/SkillEditor/SkillEditorScene.unity`
- `.../SkillEditorWindow.cs:192`、`202`  
  一键切换到编辑场景/返回原场景

这让技能编辑器拥有独立稳定的预览环境，避免污染业务场景。

## 4.3 预览角色与运行组件注入

关键代码：

- `.../SkillEditorWindow.cs:222-257`  
  预览角色预制体变更时自动实例化到 `PreviewCharacterRoot`

意义：编辑器直接驱动与运行时同名的 `SkillPlayer`，保证预览行为与实战行为同构。

## 4.5 五条核心轨道（数据即配置）

SkillClip 包含五类数据（`Assets/Scripts/Core/Config/Skill/SkillClip.cs:16-25`）：

- 动画：`SkillAnimationData`（字典：帧 -> 动画事件）
- 音效：`SkillAudioData`（列表）
- 特效：`SkillEffectData`（列表）
- 攻击检测：`SkillAttackDetectionData`（列表）
- 自定义事件：`SkillCustomEventData`（字典：帧 -> 事件）

轨道类与数据一一对应：

- `AnimationTrack.cs`
- `AudioTrack.cs`
- `EffectTrack.cs`
- `AttackDetectionTrack.cs`
- `EventTrack.cs`

### 4.5.1 动画轨道

- 拖拽 `AnimationClip` 到轨道自动创建事件（`AnimationTrack.cs:55-129`）
- 自动处理“片段重叠冲突”与“持续帧截断”（`AnimationTrack.cs:73-111`）
- 支持拖动起始帧并同步回配置索引（`AnimationTrackItem.cs:135-143`）
- 支持基于根运动采样角色预览位置（`AnimationTrack.cs:188-282`）

### 4.5.2 攻击检测轨道（技能编辑器的关键价值点）

- 多子轨道管理（增删改名/交换）（`AttackDetectionTrack.cs:18-99`）
- 支持检测类型：`Weapon / Box / Sphere / Fan`（`SkillAttackDetectionEvent.cs:76-83`）
- 检测参数和命中参数同屏可配（`SkillAttackDetectionEventInspector.cs:26-334`）
- Scene 视图下支持 Handle 直接调参（`AttackDetectionTrackItem.cs:148-205`）
- Gizmos 按当前帧实时绘制（`AttackDetectionTrack.cs:118-145`）

这条轨道直接减少“盲调碰撞体 + 反复进场测试”的成本，是你可以重点讲的校招亮点。

### 4.5.3 音效轨道

- 支持拖拽 `AudioClip` 到子轨道（`AudioTrackItem.cs:137-165`）
- 支持播放时从中间帧按比例续播（`AudioTrack.cs:106-129`）
- 编辑器反射 `UnityEditor.AudioUtil` 做预览播放（`EditorAudioUtility.cs:17-40`）

### 4.5.4 特效轨道

- 拖拽 `Prefab` 自动写入默认参数与时长（`EffectTrackItem.cs:153-181`）
- 自动计算粒子最大持续时间转帧数（`SkillEffectEventInspector.cs:83-95`）
- Scene 中可直接 TransformHandle 调整位置旋转缩放（`EffectTrackItem.cs:257-297`）
- 按当前时间轴帧模拟粒子播放进度（`EffectTrackItem.cs:188-219`）

### 4.5.5 自定义事件轨道

- 双击空白帧创建事件（`EventTrack.cs:38-46`）
- 事件类型下拉 + 四类参数（int/float/string/object）编辑（`SkillCustomEventInspector.cs:17-99`）

## 5. 技能系统完整执行链路（编辑态 -> 运行态）

## 5.1 一图总览

```text
SkillEditorWindow
  -> 各 Track 编辑数据（Animation/Audio/Effect/Attack/Event）
  -> 写回 SkillClip(Asset)
  -> SkillConfig.Clips 引用 SkillClip
  -> CharacterConfig.SkillConfigList 引用 SkillConfig
  -> PlayerSkillBrainBase.Init 读取 DataManager 技能学习数据并 AddSkill

  -> SkillPlayer 按帧 Tick 五类事件
  -> SkillBehaviourBase.Before/After* 处理事件语义
  -> ICharacter 接口落地（位移/旋转/武器/加Buff）
  -> ECS/Mono 命中与特效音效生效
```

## 9. 性能与工程化点

- `Overlap*NonAlloc` 路径用于命中/拾取，降低 GC 风险
- 对象池用于特效与对象复用
- asmdef 分层降低编译耦合
- 编辑器端内置手动 Undo 快照与脏标记保存，减少误操作损耗

## 11. 面试讲解提纲（建议 3 分钟版本）

1. 先讲问题：传统技能调参需要频繁进场，效率低。
2. 再讲方案：我做了 SkillEditor，五轨统一编辑，场景中实时预览。
3. 再讲链路：编辑数据落到 SkillClip -> SkillConfig -> SkillBrain -> SkillPlayer 帧驱动。
4. 再讲难点：
   - 攻击检测可视化（Box/Sphere/Fan）
   - 动画根运动采样与预览同步
   - Undo 快照和资产落盘一致性
5. 再讲结果：技能迭代效率提升、联调成本降低、运行时与编辑器行为一致。
